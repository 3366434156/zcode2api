后台自动刷新各账号额度与状态的周期（默认 1800 秒 = 30 分钟；billing 查询本身是上游风控信号源，别调太小）。设为 0 关闭自动刷新（仍可手动刷新）。修改后即时生效。
每个账号同时处理的最大请求数；某账号并发满时自动切下一个账号。默认为 1（上游对「账号 × 模型」并发硬限很低，超了会回 429 code 3009），并发能力因此等于账号数。设为 0 不限制。修改后即时生效。
周期对全部 JWT 账号执行活动套餐领取（激活上报 + 查询 + 领取）。设为 0 关闭轮次，仅入池/手动触发。默认 3600（1 小时）。修改后即时生效。
模型兜底（自动换模型）
额度按「账号 × 模型」计：某个模型在全池用完后自动换下一个模型，客户端无感；请求模型永远排第一。 单次请求可用请求头 x-zcode-no-fallback: 1 关闭；响应头 x-zcode-model 回报实际服务的模型。
关闭后，请求模型在全池都不可用时直接回错误，不再尝试其它模型（仍然会换号）。
从左到右依次尝试，有余额的排前面（稳定排序，不打乱你写的顺序）。留空 = 不兜底。请求模型自己永远排第一，不用写进来。
某模型被判定「全池不可用」后跳过它的秒数（默认 600）。0 = 不跳过，每次照试（会多打几次必失败的上游请求）。

使用说明
· 在「账号池」粘贴 Coding Plan JWT 或 API Key 即可加入轮询。
· 请求按 round-robin 分发；某账号额度用完会自动切到下一个账号。
· 账号额度、状态在「账号池」页实时刷新展示。
· 对话端点：/v1/messages（兼容 Anthropic Messages 协议）。
· 局域网访问：同一网段用 http://<本机IP>:3000/admin 打开本后台 （首次需放行防火墙：仓库里双击 allow-firewall.bat）。
