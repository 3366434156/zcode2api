一键接入做了什么
· 只往客户端配置里写一条 provider（id 固定为 zcode2api），其它 provider、routing group、自定义字段原样保留。
· 写入前自动备份原件（首次接入前的版本永久保留），文件以 0600 落盘，采用临时文件 + 原子替换。
· 「一键还原」回到首次接入前的字节；若期间你或客户端自己改过该文件，则只摘掉本网关那一条，不覆盖你的改动。
· 客户端不在本机（例如 magpie 跑在另一台电脑）时，可改用命令行： python -m app.clients apply --client magpie --base-url <网关地址> --key <网关 Key>
鉴权
用于登录此管理后台。修改后需用新密码重新登录。
当前仍是默认口令，生产环境请立即更换。
设置后，调用 /v1/messages 须携带 Authorization: Bearer <key> 或 x-api-key。清空并保存可关闭校验（生产必须配置）。输入框显示掩码，未改动保存不会覆盖原值。
后台自动刷新各账号额度与状态的周期（默认 1800 秒 = 30 分钟；billing 查询本身是上游风控信号源，别调太小）。设为 0 关闭自动刷新（仍可手动刷新）。修改后即时生效。
每个账号同时处理的最大请求数；某账号并发满时自动切下一个账号，所有账号都满时请求排队等空位（默认最多等 120s，可用环境变量 ZCODE_QUEUE_WAIT_MAX 调整，0 = 不排队直接拒绝）。默认为 1（上游对「账号 × 模型」并发硬限很低，超了会回 429 code 3009），并发能力因此等于账号数。设为 0 不限制。修改后即时生效。
所有会话的流量都尽量留在同一个账号上，只有它不可用（额度用完 / 冷却 / 并发满 / 凭证失效）才轮询下一个——上游按「账号 × 模型」计并发租约，摊开到多个号并不能提高并发上限，只会让请求监控看起来一直在跳号。会话粘性优先级更高：同一段对话先回它上次用的号。默认开启。
周期对全部 JWT 账号执行活动套餐领取（激活上报 + 查询 + 领取）。设为 0 关闭轮次，仅入池/手动触发。默认 3600（1 小时）。修改后即时生效。
模型兜底（自动换模型）
额度按「账号 × 模型」计：某个模型在全池用完后自动换下一个模型，客户端无感；请求模型永远排第一。 单次请求可用请求头 x-zcode-no-fallback: 1 关闭；响应头 x-zcode-model 回报实际服务的模型。
关闭后，请求模型在全池都不可用时直接回错误，不再尝试其它模型（仍然会换号）。
从左到右依次尝试，有余额的排前面（稳定排序，不打乱你写的顺序）。留空 = 不兜底。请求模型自己永远排第一，不用写进来。
某模型被判定「全池不可用」后跳过它的秒数（默认 600）。0 = 不跳过，每次照试（会多打几次必失败的上游请求）。
与网关调度用的是同一份台账（额度快照 + 实测成功记录）。「立即恢复」只清该模型的死标记，下一次请求会重新验证。

使用说明
· 在「账号池」粘贴 Coding Plan JWT 或 API Key 即可加入轮询。
· 请求按 round-robin 分发；某账号额度用完会自动切到下一个账号。
· 账号额度、状态在「账号池」页实时刷新展示。
· 对话端点：/v1/messages（兼容 Anthropic Messages 协议）。
· 局域网访问：同一网段用 http://<本机IP>:3000/admin 打开本后台 （首次需放行防火墙：仓库里双击 allow-firewall.bat）。
